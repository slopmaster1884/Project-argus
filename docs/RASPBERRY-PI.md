# Argus на Raspberry Pi: готовый образ «Argus Node»

[English version](RASPBERRY-PI.en.md) · Linux-ПК как нода: [LINUX.md](LINUX.md)

Записываешь образ на microSD-карту, вставляешь её в Raspberry Pi, включаешь — и через пару минут Pi сам появляется в Argus в списке **«Найдено в сети»**. Терминал не нужен, клавиатура и монитор тоже.

Внутри обычная **Raspberry Pi OS Lite (64-bit)** и нода Argus, которая запускается сама при каждом включении.

## Что понадобится

| Что | Подробности |
|---|---|
| Raspberry Pi | **5, 4, 400, 500, 3 или Zero 2 W**: нужна 64-битная модель. Чем больше памяти, тем лучше: Pi 5 на 8 или 16 ГБ отдаст Argus больше всего. Pi 1, Pi 2 и первый Zero не подойдут. |
| microSD-карта | от **8 ГБ**. Всё, что на ней было, сотрётся. |
| Блок питания | родной для твоей модели. От слабого Pi тормозит и перезагружается. |
| Сеть | та же домашняя сеть, что у компьютера с Argus: **кабель** в роутер или **Wi-Fi**. |
| Компьютер | с картридером и программой **Raspberry Pi Imager 2.0.3 или новее** ([скачать](https://www.raspberrypi.com/software/)). |

## Шаг 1. Скачай образ

Открой [страницу релизов](https://github.com/slopmaster1884/Project-argus/releases) и найди в последнем релизе:

- `argus-node-pi-arm64.rpi-imager-manifest`: маленький файл, **его и бери**, если Pi будет подключён по Wi-Fi;
- `argus-node-pi-arm64.img.xz`: сам образ (~0,6 ГБ), если подключишь кабелем;
- `argus-node-pi-arm64.img.xz.sha256`: контрольная сумма (по желанию).

## Шаг 2. Запиши карту

### Вариант А: Wi-Fi (или нужен вход по SSH)

1. Дважды щёлкни по скачанному файлу `argus-node-pi-arm64.rpi-imager-manifest`, и откроется Raspberry Pi Imager.
   Если не открылся, запусти Imager сам: **App Options → Content Repository → Edit → Use custom file**, выбери этот файл и нажми **Apply & Restart**.
2. **Устройство:** выбери свою модель Raspberry Pi.
3. **ОС:** выбери **Argus Node (Raspberry Pi OS Lite 64-bit)**. Imager сам скачает образ и проверит его.
4. **Накопитель:** выбери свою microSD-карту. Проверь букву диска, чтобы не стереть флешку!
5. **Настройки (Customisation):**
   - **Hostname:** оставь `argus-node` (или впиши своё, если Pi будет несколько);
   - **Wi-Fi:** имя сети, пароль и **страну** (Russia = RU). Без страны Wi-Fi может не включиться;
   - **Пользователь и пароль:** придумай, если хочешь заходить на Pi по SSH. Для работы ноды он не нужен;
   - **SSH:** включи, если задал пользователя.
6. **Write / Записать** и подожди, пока Imager запишет и проверит карту.

### Вариант Б: кабель (без всяких настроек)

1. Открой Raspberry Pi Imager: **Устройство** → твоя модель, **ОС** → прокрути вниз → **Use custom** → выбери `argus-node-pi-arm64.img.xz`.
2. **Накопитель:** твоя microSD-карта → **Записать**.

Imager не предложит настройки (Wi-Fi, пользователь): для своих файлов-образов Imager 2.x их отключает. Для кабеля они не нужны. Нужен Wi-Fi? Бери вариант А или смотри [«Wi-Fi без Imager»](#wi-fi-без-imager).

## Шаг 3. Включи

1. Вставь карту в Raspberry Pi. Для варианта Б воткни кабель от роутера.
2. Подключи питание.
3. Подожди **~2 минуты**. При первом включении Pi растягивает систему на всю карту и может сам один раз перезагрузиться, это нормально.

## Шаг 4. Добавь ноду в Argus

На главном компьютере: **Argus → Cluster → «Найдено в сети»**. Там появится нода с именем вроде **«Pi 5 · 3F2A»** (модель и последние 4 знака сетевого адреса, у каждого Pi свои). Нажми **«Добавить»**. Статус станет зелёным.

Всё. Pi можно убрать на полку: при каждом включении нода стартует сама.

## Защищённый режим (PIN), без монитора и клавиатуры

Без защищённого режима к ноде может подключиться любое устройство в твоей сети. С ним подключаются только компьютеры, которые ввели PIN (нужен Argus 0.3.5+; подробности и честная модель угроз в [SECURITY.md](SECURITY.md)).

1. Вставь карту в компьютер. Появится диск **bootfs**.
2. Открой на нём файл `argus.conf` в Блокноте. Найди строку `#ARGUS_SECURE=1`, удали `#` в начале и сохрани.
3. Верни карту в Pi, включи его и подожди ~2 минуты: нода придумает PIN и запишет его на карту.
4. Выключи Pi (просто отключи питание), вставь карту в компьютер и открой на диске **bootfs** файл **`argus-pin.txt`**: там 6-значный PIN.
5. Верни карту, включи Pi. В Argus: «Найдено в сети» → «Добавить» → введи PIN.

PIN **не меняется** при перезагрузках. Новый появится, только если кто-то 5 раз введёт неверный PIN или ты сбросишь сопряжение (ниже); тогда снова загляни в `argus-pin.txt`. После сопряжения PIN больше не нужен: компьютер запоминает ключ ноды. Если заходишь по SSH, PIN можно посмотреть и так: `cat /boot/firmware/argus-pin.txt`.

Забыть все сопряжённые компьютеры: создай на диске **bootfs** пустой файл `argus-reset-token` (без расширения). При следующем запуске нода удалит ключ, а файл исчезнет сам.

## Настройки: файл `argus.conf`

Лежит на диске **bootfs** (на самом Pi это `/boot/firmware/argus.conf`). Строка с `#` в начале выключена. Поменял, тогда перезапусти Pi (или `sudo systemctl restart argus-node`).

| Строка | Что делает |
|---|---|
| `ARGUS_SECURE=1` | защищённый режим, PIN в `argus-pin.txt` |
| `ARGUS_NODE_NAME=Pi на кухне` | своё имя в Argus вместо «Pi 5 · 3F2A» |
| `ARGUS_THREADS=3` | сколько ядер отдавать (по умолчанию все) |
| `ARGUS_PORT=50052` | порт (менять не нужно) |
| `ARGUS_BEACON_TARGET=192.168.1.10` | IP главного ПК, если нода не появляется в «Найдено в сети» (роутер режет широковещание) |

## Wi-Fi без Imager

Записал образ через «Use custom» (вариант Б), а кабеля нет? Вставь карту в компьютер, открой на диске **bootfs** файл `network-config` и допиши в конец (отступы пробелами, не Tab):

```yaml
network:
  version: 2
  wifis:
    renderer: NetworkManager
    wlan0:
      dhcp4: true
      regulatory-domain: "RU"
      access-points:
        "Имя-твоей-сети":
          password: "пароль-от-wifi"
      optional: true
```

Сохрани, верни карту в Pi. Это работает только **до первого включения** (cloud-init применяет файл один раз). Если Pi уже включали, проще записать карту заново.

## Вход по SSH (по желанию)

SSH включён, но **пароля по умолчанию нет**: войти можно, только если в Imager ты задал пользователя (вариант А). Тогда:

```
ssh твой-пользователь@argus-node.local
```

(не находит `argus-node.local`? Возьми IP Pi из настроек роутера.)

| Что | Команда |
|---|---|
| Нода работает? | `systemctl status argus-node` |
| Журнал | `journalctl -u argus-node -f` (выход Ctrl+C) |
| Перезапуск | `sudo systemctl restart argus-node` |
| Имя ноды | `cat /var/lib/argus-node/node-name` |
| Какая сборка | `cat /opt/argus-node/BUILD-INFO` |

## Что внутри образа

- Raspberry Pi OS Lite (64-bit) на Debian Trixie, как с сайта Raspberry Pi: все её первые настройки (cloud-init, Imager) работают как обычно.
- `/opt/argus-node`: тот же скрипт ноды, что для Linux ([LINUX.md](LINUX.md)), и статические сборки rpc-server для arm64, те же, что в Argus Node на Android. Интернет ноде не нужен, ничего не скачивается.
- Служба `argus-node` стартует при включении и работает от отдельного пользователя `argus` без прав администратора. Если упадёт, перезапустится сама.
- Имя компьютера `argus-node`. Имя ноды в Argus задаётся при первом включении: «Pi 5 · 3F2A».
- SSH включён штатным способом Raspberry Pi (файл `ssh` на диске bootfs), пароля по умолчанию нет.
- Подкачка: zram, как в обычной Raspberry Pi OS Trixie (пакет rpi-swap), без изменений.
- Файрвола нет (в Raspberry Pi OS его нет по умолчанию), порты 50052 (TCP) и 50053 (UDP) открывать не нужно. Поставишь `ufw` сам? Тогда открой порт: `sudo ufw allow 50052/tcp`.

## Несколько Raspberry Pi

Каждая нода сама получает своё имя (по сетевому адресу), так что в Argus они не перепутаются. Имя компьютера у всех одинаковое, `argus-node`. Если заходишь по SSH, в Imager дай каждому своё (`argus-node-1`, `argus-node-2`…).

## Обновление

Вышел новый образ, тогда просто запиши карту заново. Перед этим скопируй с диска **bootfs** свой `argus.conf`, если что-то в нём менял. После перезаписи Pi получит то же имя ноды (оно считается по сетевому адресу), но в защищённом режиме компьютеры придётся сопрячь заново.

## Если не работает

| Что видишь | Что делать |
|---|---|
| Ноды нет в «Найдено в сети» через 3–4 минуты | Pi и компьютер должны быть в одной сети (не гостевой). Проверь, что Pi появился в списке устройств роутера. Wi-Fi: проверь имя сети, пароль и страну в Imager. Pi 5/4 + Wi-Fi 5 ГГц: попробуй 2,4 ГГц. |
| Pi есть в роутере, но не в Argus | Роутер может блокировать широковещание («изоляция клиентов», AP isolation). Нажми в Argus **«Добавить ноду по IP»** и впиши `IP-адрес-Pi:50052`, или впиши IP главного ПК в `ARGUS_BEACON_TARGET` в `argus.conf`. |
| Нода появилась, но после «Добавить» OFFLINE | Включён защищённый режим? Введи PIN из `argus-pin.txt`. Старый Argus (до 0.3.5) защищённый режим не умеет: обнови Argus или выключи режим. |
| Красный индикатор мигает, Pi перезагружается | Слабый блок питания или кабель. Возьми родной. |
| Imager не предлагает настройки | Ты выбрал файл через «Use custom». Для Wi-Fi открой файл `.rpi-imager-manifest` (вариант А). И обнови Imager до 2.0.3+: Imager 1.x настройки для этого образа молча не применит. |
| «rpc-server протокол v… — нужен v8» | Версия образа не совпадает с Argus. Запиши образ из того же релиза, что и твой Argus. |

Не помогло? Открой [Issue](https://github.com/slopmaster1884/Project-argus/issues/new) и приложи модель Pi, версию Argus и (если есть SSH) вывод `journalctl -u argus-node -n 50 --no-pager`.

## ⚠ Безопасность

Без защищённого режима нода слушает порт 50052 без пароля. Ставь её **только дома**, не пробрасывай порты 50052/50053 в интернет. PIN-режим защищает от чужих устройств в сети, но трафик не шифрует ([SECURITY.md](SECURITY.md)).

## Собрать образ самому

Образ собирает GitHub Actions: **Actions → pi-image → Run workflow**. Через ~20 минут образ лежит в артефактах запуска. Сборка берёт официальный образ Raspberry Pi OS Lite, проверяет его контрольную сумму и дорабатывает на arm64-машине (`scripts/pi-image/build-image.sh`). Вручную, на arm64-Linux с правами root:

```
sudo scripts/pi-image/build-image.sh 2026-10-06-raspios-trixie-arm64-lite.img.xz out/argus-node-pi-arm64.img
```
