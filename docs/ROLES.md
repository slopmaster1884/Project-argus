# Роли нод (план от 2026-11-01, статус на 0.4)

English: [ROLES.en.md](ROLES.en.md)

> **Статус 0.4:** **Помощник** — обычная функция (переключатель «Роли» в Кластере включён по умолчанию; кто в 0.3.x
> назначил Помощника и выключил эксперимент — остаётся выключенным). Модель получает только нода с достаточным запасом
> свободной памяти. **Маршрутизация задач** (тип задачи → роль → нода, фолбэк на ПК) — в «Очереди», подзадачах агента
> и «Поиске по файлам». **Поиск** — роль ноды (llama-server `--embedding` :50060, Argus Node 0.4), фолбэк — эмбеддинги на ПК.
>
> **Статус 0.3.3 (нода):** единый протокол ролей (ниже), Голос (whisper-server) и Библиотека (kiwix-serve) в APK, телеметрия температуры/батареи.
>
> **Статус:** в 0.3.2 сделаны прогрев, тест скорости нод, деление слоёв по скорости, роли «Авто / Часть модели / Свободна» и экспериментальная роль **Помощник** (включается переключателем «Роли» в Cluster). Поиск, Голос и Библиотека — ещё план.

Сейчас все ноды работают как одна модель (pipeline по слоям): каждый токен проходит GPU → нода 1 → нода 2 по очереди. Лишние ноды добавляют память, но не скорость.

Режим «Роли»: каждое устройство одновременно делает свою работу, а Argus на ПК раздаёт задачи.

## Роли
| Роль | Что делает | Движок на ноде | Порт (adb forward) |
|---|---|---|---|
| Часть модели | слои главной модели (как сейчас) | rpc-server | 50052 (ПК 50052+) — ✅ |
| Помощник | маленькая модель 0.6–4B: сводки, названия чатов, перевод, куски заданий «Очереди», подзадачи агента | llama-server (arm64) | 50062 (ПК 50162+) — ✅ 0.4, по умолчанию |
| Поиск | эмбеддинги для поиска по файлам (RAG, вкладка «Знания») | llama-server --embedding | 50060 (ПК 50160+) — ✅ 0.4 (Argus Node 0.4) |
| Голос | распознавание речи | whisper.cpp server | 50061 — ✅ 0.3.3 |
| Библиотека | офлайн-Википедия | kiwix-serve | 50063 — ✅ 0.3.3 |
| Свободна | ничего, не греется | — | — — ✅ 0.3.2 |

## Как работает
1. Автотест каждой ноды при подключении: скорость (tok/s на эталонном слое), RAM, температура.
2. Авто-раскладка: главная модель берёт GPU + минимум самых быстрых нод, чтобы влезть; остальные — «Свободна». Роли Помощник / Поиск / Голос / Библиотека пока назначает пользователь (авто-назначения по RAM/скорости нет); модель роли нода получает только при достаточной свободной RAM.
3. Модели для ролей качаются на ПК и передаются на ноду (adb push по USB или HTTP :50055 по Wi‑Fi), хранятся в памяти приложения ноды.
4. Нода-приложение получает команду «роль X, модель Y» и запускает нужный движок вместо/рядом с rpc-server.
5. На ПК очередь задач: тип задачи → роль → нода. Если нода пропала — задача уходит на CPU ПК или главную модель (✅ 0.4, см. «Маршрутизация задач»).
6. В чате видно, кто что сделал (Note10+ нашёл 3 фрагмента, A52 распознал голос).

## Пример (железо автора)
- GTX 960 + быстрый телефон: Qwen3 4B — чат ~14 tok/s.
- Note10+ (12 ГБ): Поиск + Помощник (Qwen3 1.7B).
- A52: Голос (whisper small).

## Ограничения
- Один ответ быстрее не станет; быстрее и богаче становится всё вместе.
- Нагрев/батарея телефонов, RAM каждой ноды.

## Маршрутизация задач (0.4)

Правила — чистые функции в `desktop/src-tauri/src/route.rs` (с юнит-тестами); их используют `queue.rs`, `helper.rs`, `rag.rs`.

| Тип задачи | Роль | Нода | Фолбэк |
|---|---|---|---|
| сводка / название чата, перевод, подзадача агента | Помощник | готовый Помощник с наименьшим числом запросов (USB раньше Wi-Fi) | главная модель на ПК |
| «Своё задание» в «Очереди» | — | — | только главная модель |
| эмбеддинги («Знания», `search_files`) | Поиск | нода с ролью «Поиск» (свой адрес → ноды → ПК) | llama-server с той же моделью на ПК (:50070) |
| распознавание речи | Голос | телефон с whisper | (как в 0.3.3) |

- **Фолбэк молча:** если нода не ответила или пропала посреди задания, этот кусок переделывается на следующей ноде или
  на главной модели; нода исключается до конца файла/подзадачи. Если нет ни ноды, ни запущенной модели, «Очередь» ждёт.
- **Очередь:** у задания есть маршрут `auto` (по умолчанию для перевода и пересказа: Помощник, если свободен) или `main`
  (только главная модель; так работают «Своё задание» и задания, сохранённые 0.3.x). Для Помощника куски вдвое меньше
  (у него контекст 4096). В карточке задания видно, кто выполнял («главная модель», «Помощник «Note10+»»).
- **Подзадачи агента:** инструмент `subtask` (`summarize | translate | extract`, текст до 60 000 символов) → Rust
  `subtask_run`; длинный текст режется на куски, каждый — Помощнику или главной модели. Действие только читает текст,
  поэтому не считается опасным (подтверждение — как у остальных инструментов).
- **Безопасность памяти:** Помощнику нужна свободная RAM ≈ модель × 1.5 + 512 МБ, Поиску ≈ модель + 384 МБ
  (`route::helper_need_mb`, `search_need_mb`). Нода с меньшим запасом модель не получает (уже работающая — сохраняет),
  в интерфейсе — «Мало свободной памяти…», задачи идут на ПК. Нода, не сообщившая RAM (0), не блокируется.
- **Поиск и индекс:** нода получает тот же файл, что ПК запускает у себя (`nomic-embed-text-v1.5.Q8_0.gguf`), поэтому
  индекс, построенный на ноде, работает и на ПК, и наоборот. Если запасной сервис работает с другой моделью — ошибка
  с просьбой переиндексировать (как раньше).

## Протокол ролей ноды (Android, с 0.3.3, versionCode 7; «Поиск» — с 0.4, versionCode 8)

rpc-server («Часть модели») работает всегда; остальные роли запускаются **рядом** с ним и не исключают друг друга.
rpc-server берёт большие ядра (`-t` = big+prime, `force_threads` — переопределение), роли Помощник, Голос и Поиск по умолчанию —
малые ядра (`-t` = число малых ядер, минимум 2); если работает `toybox taskset`, процесс роли прикрепляется к малым ядрам
(best effort; если потоков больше, чем малых ядер, — без привязки).

### Команды по USB (adb)
`adb shell am start-foreground-service -n com.harkcluster.node/.RpcService <extras>`

| Extra | Значение |
|---|---|
| `--es role rpc\|helper\|voice\|library\|search\|idle` | запустить роль (можно через запятую). `rpc` — ничего не делает (rpc-server и так идёт), `idle` — остановить все роли кроме rpc |
| `--es role_stop helper\|voice\|library\|search\|all` | остановить роль(и) и **забыть** назначение (обрабатывается до `role`) |
| `--es helper_model <file.gguf> --es helper_url <url> [--el helper_size N] [--ei helper_threads N]` | Помощник (llama-server). Без `role` тоже работает (как в 0.3.2) |
| `--ez helper_stop true` | устаревшее = `role_stop helper` |
| `--es voice_model <file.bin> --es voice_url <url> [--el voice_size N] [--ei voice_threads N]` | Голос (whisper-server); `voice_url` обычно `http://127.0.0.1:50055/helper/<file>` (adb reverse) |
| `--es search_model <file.gguf> --es search_url <url> [--el search_size N] [--ei search_threads N]` | Поиск (llama-server `--embedding --pooling mean -c 2048`, 0.4). `role` = `search` (или `embeddings`) |
| `--es zim <file.zim>` | Библиотека: имя файла в `filesDir/zim` (или абсолютный путь). Без `zim` — последний назначенный, иначе самый новый .zim |
| `--ez wifi true\|false`, `--ei port`, `--ei force_threads` | как раньше |
| action `com.harkcluster.node.STOP` | остановить узел; назначения ролей **сохраняются** и поднимутся при следующем старте |

Назначения хранятся в SharedPreferences `node` (`role_helper`, `role_voice`, `role_library`, `role_search`) и перезапускаются после
перезапуска сервиса (START_STICKY, обновление APK, «Запустить узел»). Любая остановка роли (`role_stop`, `role=idle`,
`helper_stop`, `"<роль>": false` в ответе на маяк) работает независимо от того, откуда роль была назначена (в 0.3.2
`"helper": false` останавливал только помощника, назначенного по Wi-Fi — исправлено).

### Состояние: USB (dumpsys)
`adb shell dumpsys activity service com.harkcluster.node/.RpcService` печатает строки:
- `argus-helper state=… pct=… model=… error=…` (как в 0.3.2)
- `argus-status {json}` — **одна строка JSON** (новое в 0.3.3)
- `argus-rpc …`, `argus-bench …` (как раньше)

```json
{"argus":"status","v":1,"vn":"0.3.3","vc":7,
 "temp_c":38.5,"battery_temp_c":34.0,"cpu_temp_c":38.5,"thermal_status":0,"throttled":false,
 "battery_pct":81,"charging":true,"usb_net_ip":"192.168.42.129","wifi_ip":"192.168.1.23",
 "rpc":{"state":"linked","port":50052,"threads":4,"big_cores":4,"variant":"dotprod","mode":"usb"},
 "roles":{"helper":{"state":"ready","pct":100,"port":50062,"threads":4,"model":"Qwen3-1.7B-Q4_K_M.gguf"},
          "voice":{"state":"idle","port":50061,"pct":0,"threads":0},
          "library":{"state":"ready","port":50063,"zim":"wikipedia_ru_all_mini.zim"},
          "embeddings":{"state":"ready","port":50060,"pct":100,"threads":4,"model":"nomic-embed-text-v1.5.Q8_0.gguf"}}}
```
Состояния ролей: `idle | downloading | starting | ready | error` (+ `error`, `pct`; у library — `import_pct` пока копируется .zim).
Ключ `embeddings` есть только у Argus Node 0.4+: по нему ПК понимает, что роль «Поиск» можно предлагать (старым нодам
она не показывается). Помощник и Поиск — один бинарник; при запуске каждый убивает «осиротевшие» процессы только своего
вида (по аргументу `--embedding`).

Необязательные поля (`temp_c`, `cpu_temp_c`, `battery_pct`, `usb_net_ip`, `wifi_ip`) отсутствуют, если значение неизвестно.

- `temp_c` = max(температура батареи `EXTRA_TEMPERATURE/10`, максимум `/sys/class/thermal/thermal_zone*/temp`; зоны часто закрыты SELinux → только батарея).
- `throttled` = `PowerManager.currentThermalStatus ≥ THERMAL_STATUS_MODERATE` (Android 10+, иначе false); `thermal_status` — сырое значение 0…6.
- `usb_net_ip` — IPv4 интерфейса `rndis*`/`ncm*`/`usb*` (USB-модем).

### Состояние: Wi-Fi (маяк UDP :50053)
В JSON маяка добавлены те же поля телеметрии (`temp_c`, `battery_temp_c`, `cpu_temp_c`, `thermal_status`, `throttled`,
`battery_pct`, `charging`, `usb_net_ip`) и `"roles": {helper, voice, library}` (+ `embeddings` с 0.4). Старое поле `"helper"` осталось.
Неизвестные ключи ПК игнорирует.

Ответ ПК на маяк (`{"argus":"host",…}`) может содержать: `"helper": {file,path,size,threads} | false`,
`"voice": {file,path,size,threads} | false`, `"library": {"zim":…} | false`, `"search": {file,path,size} | false` (0.4);
отсутствие ключа — без изменений. Старые ноды неизвестный ключ `search` игнорируют.

### Библиотека на телефоне
Кнопка «Выбрать .zim» (системный выбор файла, SAF) копирует файл в `filesDir/zim` с прогрессом. Если роль Библиотека
уже работает, она переключается на новый файл. ПК включает роль `--es role library [--es zim <имя>]`.

### Подсказка о нагреве
Если телефон заряжается и `temp_c ≥ 40` или `throttled`, приложение показывает: «Если заряжается и греется — ограничь
заряд до 85% в настройках батареи».
