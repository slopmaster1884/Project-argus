# Защищённый режим RPC (PIN)

[English](SECURITY.en.md)

По умолчанию нода Argus запускает `rpc-server` из llama.cpp b12008 как есть: `-H 0.0.0.0 -p 50052`, без пароля и
без шифрования. Любое устройство в той же сети может подключиться к такой ноде и гонять на ней вычисления
(или передать ей специально испорченные данные — rpc-server не рассчитан на чужих клиентов).

**Защищённый режим** — опция, по умолчанию выключена. Он пускает к порту 50052 только те ПК, которые один раз
сопряглись с нодой по 6-значному PIN-коду.

## Как включить

**Linux-ПК / Raspberry Pi**

```bash
ARGUS_SECURE=1 bash scripts/argus-node-linux.sh
# автозапуск:  ARGUS_SECURE=1 bash scripts/argus-node-linux.sh --systemd
```

Скрипт напечатает PIN в терминале (для systemd: `journalctl --user -u argus-node` или `cat ~/.local/share/argus-node/pin`).
Нужен `python3` (только стандартная библиотека). Ключ ноды хранится в `~/.local/share/argus-node/token`.
`--reset-token` удаляет ключ: все ПК должны будут ввести PIN заново.

**Android (Argus Node)** — включите «Wi-Fi режим», затем кнопку «Защищённый режим». PIN показывается крупно
под кнопкой. По adb: `am start-foreground-service -n com.harkcluster.node/.RpcService --ez wifi true --ez secure true`.

**На ПК (Argus)** — Cluster → «Найдено в сети»: у защищённой ноды метка «🔒 PIN». «Добавить» откроет окно PIN.
При добавлении по IP («Добавить ноду по IP») PIN вводится в поле «PIN (если нода защищена)». После сопряжения
у ноды метка «🔒 защищено». Удаление ноды в Argus стирает и её ключ.

Режим можно выключить в любой момент — нода снова станет обычной. ПК, у которого сохранён ключ ноды,
**не** откатится на незащищённое подключение сам: он покажет ошибку «на ноде выключена защита? Удалите ноду и
добавьте заново». Так подменённая нода не может тихо снять защиту.

## Как это устроено

```
llama-server --rpc 127.0.0.1:<локальный порт>      (Argus, rpcauth.rs)
   └─ локальный форвардер ── TCP ──▶ шлюз ноды 0.0.0.0:50052 ──▶ rpc-server 127.0.0.1:50072
                                     (рукопожатие, затем байты как есть)
```

* Нода: `rpc-server` слушает только `127.0.0.1:50072`; порт 50052 занимает шлюз. Маяк содержит `"auth":1`.
* ПК: для каждой защищённой ноды Argus держит локальный форвардер на `127.0.0.1:<случайный порт>`.
  `--rpc` получает адрес форвардера для защищённых нод и прямой адрес для обычных — их можно смешивать.
  Проверки здоровья нод (HELLO/память) тоже идут через рукопожатие.
* Клиенты с `127.0.0.1` шлюз пропускает без рукопожатия: это adb-проброс телефона, подключённого кабелем
  (внутренний порт и так доступен с самого устройства).

### Протокол

Строки ASCII, конец — `\n`, двоичные значения в hex.

```
нода → ПК   ARGUS1 <nonce, 16 байт>              сразу после подключения
вход:
ПК → нода   AUTH <mac>        mac  = HMAC-SHA256(token, "argus-auth|" ‖ nonce)
нода → ПК   OK <smac>         smac = HMAC-SHA256(token, "argus-srv|" ‖ nonce ‖ mac)  → дальше сырые байты RPC
            ERR auth          соединение закрывается
сопряжение (SPAKE2, группа RFC 3526 2048 бит, g = 2):
ПК → нода   PAIR <X>          X = g^x · M^w
нода → ПК   PAIRB <Y>         Y = g^y · N^w
ПК → нода   PAIRC <c>         k = SHA256("argus-spake2|" ‖ nonce ‖ X ‖ Y ‖ Z ‖ w), c = HMAC(k, "c")
нода → ПК   PAIROK <enc> <s>  enc = token ⊕ HMAC(k, "k"),  s = HMAC(k, "s" ‖ enc)
            ERR pin           неверный PIN
```

`w = HMAC-SHA256("argus-pin", PIN) mod q`, `M = SHA256("argus-spake2-M")² mod p`, `N = SHA256("argus-spake2-N")² mod p`,
элементы группы кодируются как 256 байт big-endian, `w` — 32 байта. Токен ноды — 32 случайных байта.
Одинаковые реализации: `desktop/src-tauri/src/rpcauth.rs` (ПК), шлюз на python в `scripts/argus-node-linux.sh`,
`android/.../AuthGateway.kt`.

## Модель угроз — честно

**Защищает от:**

* случайных и чужих устройств в той же сети (соседи по Wi-Fi, гости, заражённый «умный» гаджет), которые
  находят порт 50052 и пытаются им пользоваться или ломать rpc-server;
* подбора: каждое подключение получает свой nonce, записанный ответ `AUTH` повторно не сработает;
* перехвата PIN при сопряжении: PIN не передаётся, а SPAKE2 не даёт подслушавшему проверять PIN-ы офлайн;
  активный атакующий получает одну попытку угадать PIN на одно сопряжение, после 5 неверных PIN нода
  генерирует новый (шанс угадать ≈ 5 из 1 000 000 на каждый PIN);
* поддельной ноды, которая выдаёт себя за сопряжённую: она не знает токен и не сможет ответить `OK <smac>`.

**НЕ защищает от:**

* **прослушивания**: после рукопожатия трафик RPC идёт **без шифрования** — веса модели, промпты (в виде
  активаций) и ответы видны тому, кто может смотреть трафик в сети;
* **активного «человека посередине»** на уже установленном соединении: он может дождаться успешного входа и
  перехватить TCP-сессию. Это не замена TLS/VPN. Для недоверенных сетей используйте WireGuard/Tailscale или USB;
* доступа к самому ПК или ноде: токен лежит открытым текстом в настройках Argus (`argus-settings.json` в папке
  конфигурации) и в файле на ноде; кто может читать эти файлы, может подключиться;
* других портов ноды: роли «Помощник»/голос/библиотека (50061, 50063 и т.д.) этой защитой не закрыты;
* уязвимостей самого rpc-server для того, у кого есть токен.

## Ограничения

* Старые версии Argus не умеют PIN и не смогут подключиться к защищённой ноде; старые ноды без защиты
  работают с новым Argus как раньше.
* «Держать модель загруженной» и защищённые ноды: форвардеры живут внутри Argus, поэтому при выходе из Argus
  движок, использующий защищённые ноды, останавливается (его соединения всё равно разорвались бы).
* «USB-модем» не используется для телефона в защищённом режиме — Argus остаётся на обычном adb-пробросе.
* Ключ привязан к адресу ноды (`lan:<ip>:<порт>`): если роутер выдал ноде другой IP, сопрягите её заново.

## Что не проверено

* Android-часть (`AuthGateway.kt`) проверена на JVM против клиентов на Rust и Python (сопряжение, вход,
  отказ по неверному ключу/PIN, смена PIN, перекачка данных), но интеграция в `RpcService`/`MainActivity`
  и работа на реальном телефоне ещё не проверены.
* Полная сборка Tauri и живой прогон с настоящим `llama-server --rpc` через форвардер не выполнялись
  (проверены `cargo check`, модульные тесты и сквозной тест форвардер ↔ шлюз ↔ эхо-сервер).
